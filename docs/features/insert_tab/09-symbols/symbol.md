# Symbol — Insert > Symbols

## What real Word does
Insert > Symbols > **Symbol** is a dropdown button. Clicking it opens a flyout with a **Recently used symbols** grid (most-recently-inserted, up to ~20; a fresh profile is pre-seeded with common glyphs: € £ ¥ © ® ™ ± ≠ ≤ ≥ ÷ × ∞ µ α β π Ω ∑ …). Clicking a glyph inserts it at the caret. Below the grid: **More Symbols…** opens the full **Symbol** dialog. Inserting a symbol raises **no** contextual tab.

The **Symbol** dialog has two tabs:
- **Symbols tab:** a **Font** dropdown (any installed font incl. "(normal text)", Symbol, Wingdings, Wingdings 2/3, Webdings, Segoe UI Symbol/Emoji); a **Subset** dropdown (Unicode blocks — Basic Latin, Latin-1 Supplement, Greek and Coptic, Currency Symbols, Letterlike Symbols, Arrows, Mathematical Operators, Geometric Shapes, Dingbats, …); the character grid; a **Recently used symbols** row; a **Character code** box with a **from:** dropdown (Unicode (hex) / ASCII (decimal) / Symbol (Decimal)); **AutoCorrect…** and **Shortcut Key…** buttons; **Insert** / **Close**. (Word also supports type-hex-then-**Alt+X** in-document.)
- **Special Characters tab:** a two-column Character | Shortcut-key list — Em Dash, En Dash, Nonbreaking Hyphen, Optional Hyphen, Em/En/¼-Em Space, Nonbreaking Space, Copyright ©, Registered ®, Trademark ™, Section §, Paragraph ¶, Ellipsis …, single/double curly quotes, No-Width Optional Break, No-Width Non Break — each with Insert / AutoCorrect / Shortcut Key.

OOXML: most symbols are plain Unicode text runs `<w:r><w:t>…</w:t></w:r>`. A symbol-font glyph carries `<w:rPr><w:rFonts w:ascii="Wingdings"/></w:rPr>` and may serialize legacy as `<w:sym w:font="Symbol" w:char="F0E0"/>`. Special characters: Nonbreaking hyphen = `<w:noBreakHyphen/>`; Optional hyphen = `<w:softHyphen/>`; Nonbreaking space, dashes, ©/®/™, ellipsis, §, ¶, curly quotes = plain Unicode runs; No-Width Optional Break = U+200B; No-Width Non Break = U+FEFF.

## Current clone state
**working** (quick grid + More Symbols dialog) / **missing** (Special Characters tab, Font selector, code-point entry). `H.symbol` → `WC.Dialogs.symbol(node)` (commands.js:398) opens a flyout (dialogs.js:67) with a fixed 8-col grid of ~48 glyphs; each cell → `WC.PM.insertSymbol(s)` (bridge/insert.ts:166), which collapses the selection to end and `insertContent(ch)` — a **real** document mutation. "More Symbols…" → `WC.Insert.symbolDialog()` (insert-features.js:288): a Subset dropdown (Common/Arrows/Math/Greek/Currency/Dingbats), a glyph grid, and a recently-used row backed by `sessionStorage 'wc-recent-sym'`. Gaps vs Word: the dropdown grid is a fixed curated set (not a true persisted MRU); the dialog is **single-tab** (no Special Characters tab); no **Font** selector; no **Character code / Alt+X** entry; subsets are 6 fixed lists (not the full Unicode/Wingdings font map); MRU is `sessionStorage` (lost on restart); no symbol-font `w:rFonts`/`w:sym` mark, so Wingdings glyphs won't round-trip as Word does.

## Can we build it in our engine?
**Verdict:** ✅ Buildable NO-FORK (core); 🟡 additive fork edits for full fidelity
**Why:** The write path already works — `WC.PM.insertSymbol` (insert.ts:166) inserts any Unicode character via the real `insertContent`, and Unicode glyphs round-trip as ordinary `<w:t>` text with the existing run/text translators (no new handler needed). So the **Symbols-tab core** (Font="(normal text)", any Unicode subset, code-point/Alt+X entry, a persisted MRU) is **purely a UI build over the existing bridge verb** — NO-FORK. The **Special Characters tab** is mostly NO-FORK too: ©/®/™/dashes/§/¶/ellipsis/curly-quotes/spaces are plain Unicode insertions, and **nonbreaking hyphen has a real round-tripping node** — `noBreakHyphen` (`extensions/no-break-hyphen/no-break-hyphen.js`, v3 handler `w/noBreakHyphen/no-break-hyphen-translator.js`) — insert it via `insertContent({type:'noBreakHyphen'})`. The fidelity gaps that DO need additive fork work: **Optional hyphen** (`<w:softHyphen/>`) has **no** node/handler (grep: zero matches), and **symbol-font glyphs** (`<w:sym w:font/w:char>` / a `w:rFonts` symbol-font run for Wingdings/Webdings) have **no** handler (grep: zero `w:sym`) — without these, Wingdings selections degrade to a substituted-codepoint text run that won't reproduce in Word. None of these is a new subsystem; they are small additive translators mirroring the existing `noBreakHyphen` pattern.

## Required structures to build it
- **PM node/extension:** reuse text runs for Unicode glyphs (no node needed); reuse the existing `noBreakHyphen` node for the nonbreaking hyphen. **Add** a `softHyphen` atom node (mirror `no-break-hyphen.js`) for Optional Hyphen; optionally a symbol-font run mark for Wingdings/Symbol glyphs.
- **Converter handler (super-converter):** text/`w:t` path exists (Unicode glyphs round-trip today); `w:noBreakHyphen` handler exists (`v3/handlers/w/noBreakHyphen/`). **Add** a `w:softHyphen` translator and a `w:sym`/`w:rFonts`-symbol-font translator under `v3/handlers/w/` for full fidelity. (Both are additive — no existing handler changes.)
- **OOXML target:** plain `<w:r><w:t>` (most glyphs + special chars); `<w:noBreakHyphen/>` (exists); **add** `<w:softHyphen/>` and `<w:sym w:font w:char>` / `<w:rFonts>` symbol-font.
- **Bridge verb(s):** reuse `WC.PM.insertSymbol(ch)` for Unicode; add thin verbs for `insertSoftHyphen` / `insertNoBreakHyphen` (and a symbol-font-aware insert if Wingdings fidelity is wanted). UI: add the Special Characters tab, Font selector, Character-code/Alt+X box, and a persisted (not sessionStorage) MRU.
- **Fork edit?** none (NO-FORK) for the Symbols-tab core, the persisted MRU, and the common special characters incl. nonbreaking hyphen. **Additive** only for Optional Hyphen (`softHyphen`) and symbol-font (`w:sym`/Wingdings) round-trip.
- **Rough size:** **S–M** (UI-heavy: tabs, font/subset/code-point widgets, persisted MRU). The two additive translators are **S** each.  •  **Dependencies:** rides the existing `insertSymbol` bridge verb + text-run converter; the nonbreaking-hyphen leg rides the shipped `noBreakHyphen` node/handler.

## Open questions for our discussion
- Scope vs effort: build the **full Symbol dialog** (Font selector + every Unicode subset + Character-code/Alt+X box + Special Characters tab + persisted MRU), or a leaner pass (add just the Special Characters tab + a real persisted MRU) since the inserts already work?
- Wingdings/Webdings fidelity: do we add the symbol-font `w:sym`/`w:rFonts` handler so symbol-font glyphs reproduce in Word, or accept Unicode-only inserts (Wingdings degrade to substituted codepoints) for v1?
- Optional Hyphen: add the small additive `softHyphen` node + `<w:softHyphen/>` translator (mirrors the existing `noBreakHyphen`), or leave it out of the Special Characters tab for v1?
- AutoCorrect… and Shortcut Key… buttons: in scope (they need an AutoCorrect map and a keyboard-customization surface, both absent), or omit them?
