# 2026-05-26 — W3 complete: data-driven Word ribbon

## What shipped

Finished **Phase W3** (command mechanism + ribbon UI). The ribbon went from a
hand-coded Home-only strip to a fully **data-driven** Word-like ribbon.

- **`tools/build_ribbon.py`** — curated Word-faithful spec (tab → group → item),
  validates every `.uno:` against `resources/command-catalog.json` and every
  icon against the Fluent name set, auto-pulls labels → `resources/ribbon.json`
  (8 tabs, 29 groups, **83 commands**) + `ribbon-icons.txt` manifest.
- **`tools/fetch_icons.py`** — pulls the 80 needed icons from pinned
  `@fluentui/svg-icons@1.1.328` (jsDelivr), recolours the single-tone fill to
  the ribbon tint → `resources/icons/*.svg`, bundled into the binary via qrc.
- **QML** — `Ribbon` / `RibbonGroup` / `RibbonButton`, generic and data-driven
  from `ribbonData` (exposed by `main.cpp`). `Main.qml` slimmed to the shell.
  Large buttons = icon+label; small = icon-only 3-row stacks; group labels
  underneath; horizontal scroll on overflow.
- **State** — `STATE_CHANGED` → `win.unoState` → toggle buttons light up,
  `disabled` greys.

See DECISIONS **D10** for the architecture + the icon-recolour-vs-runtime-tint
rationale.

## Snags hit + how solved

- **QML binding loop** on `ribbonData` — the `Ribbon`'s own property shadowed
  the context property of the same name. Renamed the component property to
  `ribbonModel`.
- **Icon recolour no-op** — the jsDelivr package SVGs carry *no* path fill
  (inherit default black), unlike the raw GitHub assets (`#212121`). Fixed
  `fetch_icons.py` to set the inherited `fill` on the `<svg>` root *and*
  recolour any explicit dark fills.
- **Group-label overlap** — narrow (1-column) groups were thinner than their
  labels. Sized `RibbonGroup` to `max(buttons, label)` width.
